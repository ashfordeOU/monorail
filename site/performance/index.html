So light you'll forget it's running

A window manager runs all day, so it has to cost next to nothing. Here is what Monorail uses, how we measured it, how every build is checked, and how to measure it on your own Mac in a minute.

Measured on a 14-inch MacBook Pro with M4 Pro, on battery, with Monorail 1.7.24 managing real windows and the Mac left idle for five minutes.

How we measure

  • CPU is the processor time Monorail used over the minute, divided by the minute. That's the same as Activity Monitor's “% CPU”, averaged, so short spikes count.
  • Idle wake-ups are how often Monorail woke the processor from rest, from top. Waking the processor is what costs battery, even when each wake is tiny.
  • Memory is the memory footprint Activity Monitor shows.
  • Idle means nobody touching the Mac. While you move windows Monorail does more, then goes quiet again within a second.

Checked on every build

Before any version is released, an automatic check starts Monorail on a Mac, leaves it alone for a minute, and fails the build if idle CPU or wake-ups go over their limits. A version that got heavier can't ship by accident.

Measure it on your Mac

Open Terminal, leave the Mac alone, and run this. It needs no password and changes nothing.

curl -fsSL https://monorail.ashforde.org/perf-check.sh | bash

It prints Monorail's CPU, idle wake-ups, memory and energy impact for one minute. For a longer run, give it the number of seconds; this one runs for an hour:

curl -fsSL https://monorail.ashforde.org/perf-check.sh | bash -s 3600

You can also see Monorail's own numbers in Settings → About → Usage, and in Activity Monitor's Energy tab.

What keeps it light

  • A native Mac app, with no web view inside.
  • It mostly reacts to the Mac's own window events, and the few regular checks slow right down when nobody is at the Mac.
  • Animations run only while something moves, and can be turned off on battery.
  • Overview previews are captured at the size they're shown, and only while the overview is open.
